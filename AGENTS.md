- Render authenticated PDF note previews from the existing authorized download bytes with client-side PDF.js; browser-native blob iframes do not consistently display inline on mobile or in embedded browsers.- Newsletter: newsletter_inscricoes só recebe escrita pela função de servidor inscreverNewsletter (Zod + service role); sem GRANT de escrita para anon/authenticated, para evitar spam direto na API.

- Financeiro interno é uma rota só (`/financeiro?aba=`), com abas por permissão de módulo (`src/lib/financeiro-abas.ts`); `/resumo` apenas redireciona. Assim cada fluxo financeiro tem um único endereço.

- Áreas do Parceiro e do Cliente são layouts de rota (`parceiro.tsx`, `area-do-cliente.tsx`) com `AreaExternaLayout`; páginas definem o menu via `useDefinirMenuArea` e só mostram esqueleto no conteúdo antes da primeira leitura, para o menu nunca desmontar.
- As chaves do Elora App ficam cifradas (AES-GCM) em `elora_credenciais`, lidas só no servidor via `src/lib/credenciais.server.ts`; nenhuma função devolve a chave ao navegador (a rota do n8n é a única exceção, protegida pelo segredo de automação).
- A configuração Elora de cada cliente vive no painel lateral da Área do cliente (`/area-do-cliente?como={id}&configurar={aba}`, regras em `src/lib/dados-elora.ts`), só para super admin; o servidor exige `is_admin` nas funções de escrita (`exigirSuperAdmin`). Endereços antigos só redirecionam; `/configurar-api` é só administração geral.
- Visões (abas) do painel do cliente ficam em `elora_dashboard_visoes`, sem acesso direto pela API; leitura e escrita só via `dashboard-visoes.functions.ts` (rascunhos e gravação só super admin), para nunca vazar rascunho ao cliente.
- Área do cliente: Painel/Conta/Minha equipe são páginas do menu (`?aba=conta|plano|equipe`, `src/lib/area-cliente-menu.ts`); "Relatório diário" é visão fixa do `VisoesPainel` e o modo Editar é controlado pela barra da super admin via ref, para haver um só lugar de edição.
- Derive the Conta contact allowance through the pure display-only helper `contatos-contratados.ts` from the authorized plan and explicit contact adjustments, excluding Setup; keep financial calculations and stored usage untouched to separate allowance from usage.

- Espelho da conta Elora: tabelas `elora_*_espelho` + `elora_sync_estado` (RLS sem policy, só servidor, lógica em `elora-espelho.server.ts`); o painel lê o espelho quando a carga está concluída, exceto clientes com `fonte_dados = 'antiga'` em `elora_integracao_contas`, para trocar de fonte sem quebrar widgets.
- Painel visual do cliente: agregação pura em `src/lib/painel-visual.ts`, lida pelo servidor em `painel-visual.functions.ts` só para clientes com espelho; mensagens só via `lerMensagensSemTexto` em `elora-espelho.server.ts`, para o texto nunca sair do servidor.
- Indicadores: cada campo de evento/condição em `elora_indicadores_config` guarda `{fonte, campo}` escolhido na configuração; o motor nunca infere a fonte, para o mesmo nome poder existir no card e no contato.
- Relatório diário por canal/atendente/equipe: suporte interno é lista global (`elora_suporte_interno`, por nome ou e-mail, nunca userId) e mapa de equipe + ignorados extra são por cliente (`elora_relatorio_corte_config`); nada de cliente ou pessoa fixo no código, porque userIds e canais mudam por conta.
